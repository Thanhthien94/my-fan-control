# App-wide minimum RPM and soft startup

In **Settings → General → App-wide minimum RPM**, enable the custom minimum, enter a value (including **0**) and choose **Apply minimum RPM**. Disable the custom minimum to use each fan's reported default. This preference is local to the app, not a property of a preset or part of preset/schedule backups.

The fixed-RPM slider uses the same lower bound. Selecting/loading a fixed preset clamps its editable RPM to the allowed range without rewriting the saved definition. Existing fixed presets below an explicit floor run at that floor. Sensor curves interpolate from this floor to each fan's own maximum. Explicit sensor selection and automatic hottest-source selection use the same calculation. Scheduled control requests carry the current app preference. macOS automatic mode is unchanged.

The default remains the reported hardware minimum. An explicitly configured custom minimum can be below that value, including 0; the reported maximum remains enforced independently for every fan. Zero is a requested target, not a guarantee that a given Mac's firmware stops the fan. Firmware may reject a low target or retain a nonzero measured speed. The driver still requires target/mode readback and returns an error when it cannot confirm the requested control state. Target readback is not proof of physical RPM.

When **Fan Longevity Protection** is enabled (the default) and an owned fan starts below 1000 RPM toward a higher target, the first command rises by at most 200 RPM (capped at 1000), then the helper increases its command at up to 200 RPM/s below 1000 and 500 RPM/s afterwards. Each fan has independent monotonic state. Repeated commands do not accelerate the ramp; elapsed-time credit is capped at 2 seconds to avoid catch-up jumps. Reductions and automatic restoration are immediate. The transient startup target may be below the configured running floor. Already-spinning fans at/above 1000 RPM without an active startup sequence follow their normal policy directly.

These are command limits; motor response and minimum starting speed depend on firmware. No measured lifetime benefit, guaranteed fan stop, physical acceleration profile or universal Mac compatibility is claimed. Thermal protection still restores automatic at 90°C, data loss or lease expiry and takes priority over startup smoothing.

Changing the setting updates active rules through the helper without modifying preset identities. It validates all resulting targets before writing. A write failure restores owned fans; an invalid setting does not replace the saved preference. If the custom floor is disabled while a zero/low fixed preset is active, that running preset is raised to the reported hardware minimum. New out-of-range fixed requests remain rejected without an explicit custom floor. Helper protocol 8 prevents an older helper silently ignoring the preference.
